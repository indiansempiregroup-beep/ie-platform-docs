## 1. Purpose

This checklist supports review of UI work before it is promoted into implementation or handoff. It ensures that design quality, accessibility, consistency, and responsiveness meet the standards expected for the IE Platform.

## 2. Checklist Categories

| Category | Review Focus |
| --- | --- |
| Accessibility | Keyboard, contrast, focus, labels, screen-reader clarity |
| Consistency | Shared components, tokens, and visual language |
| Spacing | 8-point rhythm and alignment |
| Typography | Readability, hierarchy, and scale |
| Colors | Semantic use and contrast across themes |
| Dark and Light Mode | Equivalent clarity and structure |
| Touch Targets | Minimum size and interaction comfort |
| Responsiveness | Behavior at mobile, tablet, and desktop breakpoints |
| Animation | Purposeful motion and reduced-motion support |
| Developer Review | Handoff completeness and implementation clarity |

## 3. Review Questions

- Does the experience clearly communicate the primary task?
- Are shared tokens and components used instead of local overrides?
- Does the design support keyboard and screen-reader use?
- Are spacing and typography consistent with the design system?
- Are error, empty, loading, and offline states explained clearly?
- Does the layout adapt correctly across major breakpoints?
- Are dark and light themes equally usable?

## 4. Sign-off Criteria

A screen or flow is ready for handoff when:

- It passes the accessibility review.
- It uses shared components and approved tokens.
- It is responsive and readable at the required breakpoints.
- It contains clear state handling and developer notes.
